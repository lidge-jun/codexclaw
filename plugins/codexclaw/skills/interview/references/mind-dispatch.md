# Authorized Mind dispatch

Read only when actual Mind dispatch is authorized. No-delegation means no
dispatch; forbidden tracker work remains unmet, never a fabricated scan/readiness.
The top-level main owns selection, questions, triage and state. Minds are leaf,
read-only contradiction lenses: they never ask the user, edit files/plans, write
state or spawn children. Inline reasoning is not independent Mind evidence.

Before constructing a call, read the canonical
[native transport owner](../../pabcd/references/delegation.md). Its live-schema
and actual-returned-handle rules apply; this is still Interview, not an A gate.

## MIND-SPAWN-SHAPE-01

- Keep logical role `explorer` and label `mind_<mindname>`. If the live schema
  exposes agent_type/task_name, use those supported fields. If not, put role,
  lens label and read-only scope in the message and map the returned native handle
  to the label. Do not invent arguments, IDs or native role enforcement.
- Use a NON-full-history task: V2 fork_turns:"none" only where exposed; V1 omit
  fork_context (or use supported false). A full-history fork rejects model/effort
  overrides upstream and skips the .codexclaw/subagents.json role-config injection;
  do not use it to transport a Mind snapshot.
- Select lowest-scoring dimensions, with concurrent cap 3. Preserve the five
  existing lenses: contrarian, socratic, ontologist, evaluator and simplifier.
  Pack the lens prompt plus current scores, knowns, open assumptions and draft
  plan path into each stateless task. Do not substitute a generic review request.
- Honor explicit model, effort and tier constraints. Use supported overrides or
  documented inheritance, then verify actual settings when a fixed profile matters.
  Never silently fall back or pretend an unsupported override was applied.

## Role configuration and results

Mind lenses intend the explorer role, but role-config injection depends on payload,
fork eligibility and keyword inference. A snapshot containing review/검증/검토 can
select reviewer defaults instead. That is not harmless when a fixed model/effort
was requested; inspect actual settings rather than assuming the intended profile.

For an explicitly authorized persistent configuration change, the existing command
is `cxc subagents set explorer --effort <low|medium|high|xhigh>`. For a single task,
prefer supported per-dispatch reasoning_effort. Without a fixed user constraint,
small lens work may use less reasoning than the parent; this is a cost heuristic,
not permission to change shared settings. Omitted fields may receive role defaults
or inherit the parent, depending on the actual native/hook path.

Use returned handles with the live wait/follow-up/retirement tools. Retain actual
contradiction results and their evidence; malformed or missing results are not a
completed independent scan. Main triages high contradictions into questions and
low/medium into OPEN ASSUMPTIONS, and records only actual authorized scan/tracker
work. The existing answer-provenance/readiness and completion gates remain intact.
