## 확인된 사실

- entries 레인은 `wiki_lookup.py:137-148`이 루트의 대표 문서(`100.md` 등 8개)만 후보로 읽는다. 상세 문서(`NNN_*.md`)는 대표 문서에 링크만 있어 후보가 아니다. 평가 질의 Q1(개인 이력 키워드)은 대표 문서에 0회, 상세 문서 4회(정본은 2행)라 entries 0건이 구조적으로 나온다.
- raw 레인 점수는 질의 단어별 출현 횟수 합이다. Q2(키워드 + 흔한 명사 "준비")에서 키워드 0회·"준비" 11회짜리 강의 노트가 1위가 된다.
- nodes 레인(온톨로지)은 Q1에서 정답 인물·문서 노드를 낸다. 즉 세 레인이 전부 0건인 경우는 아니고, 레인 간 점수를 합산하면 안 된다.
- Q3(자연어 "내가 만든 코딩 에이전트용 모델 라우터")는 "코딩"·"모델" 우연 히트로 일반 문서만 열고, 정답 상세 문서에는 한글 "라우터"가 없다.
- `--ns aside`(2026-09-03 추가)는 문자 검색이라 Aside 의미 검색과 다른 구현이며 정본 대체가 아니다.
- `_ingest/lexicon.json` 부재로 `entry_map.json extraTerms`가 실제로 붙지 않는다.

## 로드맵 입력

회귀 아님. `wiki_lookup.py`(2026-08-21)와 `--ns aside`(2026-09-03)는 L0 밖이고 L0은 Codex 홈 검색·쓰기 게이트만 바꿨다.

- P0 (codexclaw): `cxc-recall` 사다리에 위키 레인을 명시 — 호출 명령(`python3 ~/kim_wiki/scripts/ask.py "<q>" [--json]`), 레인별 라벨, 점수 비합산, entries 0건 시 nodes/raw가 가리키는 경로를 `rg`로 직접 확인.
- P1 (codexclaw): raw 점수를 entries/nodes와 같은 순위로 읽지 않는다는 규칙, 자연어→고유명사 재작성 예시를 위키 레인에도 적는다.
- P2 (kim_wiki 별도 과제): 후보를 상세 문서까지 확장하거나 대표 문서의 상대 링크를 follow; lexicon 생성. 이 레포에서 고치지 않는다.

검증: 스킬에 `ask.py` 호출이 있는지, Q1이 entries 0 + nodes/raw 비공백을 내는지, nodes가 가리킨 상세 문서를 `rg`로 열면 정본 행이 나오는지.
