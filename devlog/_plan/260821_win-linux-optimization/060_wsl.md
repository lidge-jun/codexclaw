# 060 - wp07 WSL detection and interop

> DIFFLEVEL-ROADMAP-01: this doc is the copy-paste-executable PRD for wp07.

Defects from 002 section D closed here: **none**. That is the finding, not an omission -
`rg` over `plugins/codexclaw`, `bin`, `cli`, and `scripts` returns zero hits for `wsl` or
`WSL` in any non-test source. codexclaw has no WSL awareness at all, so there is nothing
to fix and everything to add. Every defect in 002 is allocated to another work-phase.

The motivating evidence is in 000_plan.md: `wsl.exe` output printed as UTF-16LE mojibake
in a real session. The lesson from 001 section 2.3 is to not be in that business at all.
opencodex invokes neither `wsl.exe` nor `wslpath` anywhere; it derives everything from
`/proc/version`, `/etc/wsl.conf`, and `/proc/mounts`, which sidesteps the console code
page entirely.

Patterns adopted: 001 sections 2.1 (layered detection with injectable probes), 2.2
(`[automount] root` is parsed, never assumed), 2.3 (no subprocess parsing), 2.4 (drvfs is
a distinct reliability tier), and 1.4 (drive-letter to mount rewriting).

Why this matters for a plugin that "already runs fine under WSL": the state directory.
`.codexclaw/` under `/mnt/c` is drvfs, where the `mkdirSync` steering lock
(`steering.ts:66-88`) and the `linkSync` publish (`state.ts:200-209`) have weaker
guarantees than the code assumes. A user running codex from Windows and codexclaw from
WSL against the same checkout has two runtimes writing one state tree through two
filesystem drivers.

### 1. NEW plugins/codexclaw/components/cxc-ops/src/wsl.ts

```ts
/**
 * wsl.ts - filesystem-based WSL detection and mount-root resolution.
 *
 * Deliberately NO `wsl.exe` / `wslpath` subprocess. `wsl.exe` writes UTF-16LE to
 * stdout, so every consumer needs a BOM-aware decoder, and a wrong guess about
 * the console code page produces a plausible-but-wrong path. The kernel already
 * publishes everything needed in `/proc` and `/etc` (opencodex home.ts:82-119).
 *
 * Every probe is a defaulted parameter so both branches run on one CI OS.
 */
import { readFileSync } from "node:fs";

export interface WslDeps {
  platform?: NodeJS.Platform;
  env?: NodeJS.ProcessEnv;
  /** `/proc/version` contents, or null when unreadable. */
  procVersion?: string | null;
  /** `/etc/wsl.conf` contents, or null when absent. */
  wslConf?: string | null;
  /** `/proc/mounts` contents, or null when unreadable. */
  procMounts?: string | null;
}

function readOrNull(path: string): string | null {
  try {
    return readFileSync(path, "utf8");
  } catch {
    return null;
  }
}

/**
 * True when this process runs inside WSL.
 *
 * Env vars first (`WSL_DISTRO_NAME` / `WSL_INTEROP` are set by the init process and
 * are the cheapest signal), then `/proc/version`, which carries "microsoft" in the
 * kernel string on both WSL1 and WSL2. Non-linux platforms short-circuit false:
 * a Windows-side process is not "in WSL" even when WSL is installed.
 */
export function isWslRuntime(deps: WslDeps = {}): boolean {
  if ((deps.platform ?? process.platform) !== "linux") return false;
  const env = deps.env ?? process.env;
  if (env.WSL_DISTRO_NAME || env.WSL_INTEROP) return true;
  const version = deps.procVersion !== undefined ? deps.procVersion : readOrNull("/proc/version");
  return /microsoft|wsl/i.test(version ?? "");
}

/**
 * The `[automount] root` from `/etc/wsl.conf`, defaulting to `/mnt`.
 *
 * Hardcoding `/mnt` is wrong on any distro whose user set `root = /` (a common
 * config for shorter paths, making the Windows C: drive `/c`). Comments and quotes
 * are stripped, the key match is case-insensitive, and a non-absolute value falls
 * back rather than producing a relative mount path (opencodex home.ts:51-72).
 */
export function automountRoot(deps: WslDeps = {}): string {
  const conf = deps.wslConf !== undefined ? deps.wslConf : readOrNull("/etc/wsl.conf");
  if (!conf) return "/mnt";
  let inAutomount = false;
  for (const rawLine of conf.split(/\r?\n/)) {
    const line = rawLine.replace(/#.*$/, "").trim();
    if (line.length === 0) continue;
    const section = /^\[(.+)\]$/.exec(line);
    if (section) {
      inAutomount = section[1].trim().toLowerCase() === "automount";
      continue;
    }
    if (!inAutomount) continue;
    const kv = /^([A-Za-z]+)\s*=\s*(.+)$/.exec(line);
    if (!kv || kv[1].toLowerCase() !== "root") continue;
    const value = kv[2].trim().replace(/^["']|["']$/g, "");
    if (!value.startsWith("/")) return "/mnt";
    return value.replace(/\/+$/, "") || "/";
  }
  return "/mnt";
}

/** Escape a literal for RegExp embedding. */
function escapeRegExp(value: string): string {
  return value.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}

/**
 * True when `dir` sits on a Windows drive mounted into WSL.
 *
 * The root is escaped before regex use because it comes from a user-editable
 * config file (opencodex shim.ts:494-498).
 */
export function isWindowsInteropDir(dir: string, root = "/mnt"): boolean {
  const trimmed = root.replace(/\/+$/, "");
  const escaped = escapeRegExp(trimmed);
  return new RegExp(`^${escaped}/[a-z](/|$)`, "i").test(dir);
}

/**
 * Rewrite a Windows `USERPROFILE` into its WSL mount path, or null when it does
 * not look like one.
 *
 * Backslashes are normalized first, then an ANCHORED drive-letter pattern runs,
 * and the drive is lowercased: `/mnt/C` does not exist while `/mnt/c` does
 * (opencodex home.ts:22-29).
 */
export function windowsHomeToWslPath(value: string, root = "/mnt"): string | null {
  const normalized = value.replaceAll("\\", "/");
  const match = /^([A-Za-z]):\/Users\/([^/]+)$/.exec(normalized);
  if (!match) return null;
  const base = root === "/" ? "" : root.replace(/\/+$/, "");
  return `${base}/${match[1].toLowerCase()}/Users/${match[2]}`;
}

export type FilesystemTier = "native" | "drvfs" | "9p" | "unc" | "unknown";

/**
 * Classify the filesystem a path lives on.
 *
 * Detecting WSL is not enough. State on drvfs or a UNC share appears to lock and
 * then does not, so lock-dependent features need a specific refusal rather than a
 * mysterious later failure (opencodex native-main-owner.ts:76-92).
 */
export function filesystemTier(path: string, deps: WslDeps = {}): FilesystemTier {
  const platform = deps.platform ?? process.platform;
  if (platform === "win32") {
    const normalized = path.replaceAll("/", "\\");
    if (normalized.startsWith("\\\\?\\UNC\\")) return "unc";
    if (normalized.startsWith("\\\\") && !normalized.startsWith("\\\\?\\")) return "unc";
    return "native";
  }
  if (platform !== "linux") return "native";
  const mounts = deps.procMounts !== undefined ? deps.procMounts : readOrNull("/proc/mounts");
  if (!mounts) return "unknown";
  // Longest covering mount prefix wins: /mnt/c is more specific than /.
  let best: { point: string; type: string } | null = null;
  for (const line of mounts.split(/\r?\n/)) {
    const parts = line.split(/\s+/);
    if (parts.length < 3) continue;
    const point = parts[1];
    if (path !== point && !path.startsWith(point.endsWith("/") ? point : point + "/")) continue;
    if (!best || point.length > best.point.length) best = { point, type: parts[2] };
  }
  if (!best) return "unknown";
  if (best.type === "drvfs") return "drvfs";
  if (best.type === "9p") return "9p";
  return "native";
}
```

### 2. MODIFY plugins/codexclaw/components/cxc-ops/src/doctor.ts

A new check, following the file's existing check shape. 001 section 2.5 is explicit that
dual-install diagnosis has to be a user-facing surface, because these are the bugs users
cannot diagnose themselves.

```ts
/**
 * WSL residency + state-filesystem tier.
 *
 * The dangerous configuration is not "using WSL" - it is running codex on the
 * Windows side and codexclaw on the Linux side against one checkout, so two
 * runtimes write `.codexclaw/` through two filesystem drivers. The steering lock
 * (mkdir) and the state publish (link) both assume more than drvfs guarantees.
 */
function checkWslResidency(cwd: string): DoctorCheck {
  if (!isWslRuntime()) {
    return { name: "wsl", status: "ok", detail: "not running under WSL" };
  }
  const root = automountRoot();
  const stateDir = join(cwd, ".codexclaw");
  const tier = filesystemTier(stateDir);
  if (tier === "drvfs" || tier === "9p") {
    return {
      name: "wsl",
      status: "warn",
      detail:
        `.codexclaw state lives on ${tier} (${stateDir}, automount root ${root}). ` +
        "File locking and atomic publish are weaker there than on a native Linux " +
        "filesystem, and a Windows-side codex writing the same tree can interleave. " +
        "Prefer a checkout under the Linux home, or drive codexclaw from Windows only.",
    };
  }
  return { name: "wsl", status: "ok", detail: `WSL with ${tier} state (automount root ${root})` };
}
```

Register it in the doctor's check list beside the existing entries, and include it in the
`--json` output shape unchanged (`name/status/detail` matches the current `DoctorCheck`).

### 4. Package wiring (SHARED-HELPER-01)

`wsl.ts` lives in `cxc-ops` because `doctor.ts` (section 2) is its primary consumer. But
section 3 calls `filesystemTier` from `pabcd-state/src/steering.ts`, a SEPARATE workspace
package. A `from "../../cxc-ops/src/wsl.ts"` import would not resolve at build time:
`rg` for `from "../../` across all component sources returns zero hits, because this
repo keeps components dependency-free of each other.

Same rule as 040 section 6 and 050 section 6, applied uniformly: **each consuming package
gets its own copy or two-line re-export module at the same relative path**
(`src/wsl.ts`), never a cross-package import.

| Package | File | Content |
|---------|------|---------|
| `cxc-ops` | `src/wsl.ts` | the implementation (section 1) |
| `pabcd-state` | `src/wsl.ts` | same body, copied |

`steering.ts` then imports `from "./wsl.ts"`. Every probe in `wsl.ts` is injected via
`WslDeps`, so the copy is a pure function with no state and cannot drift silently. If a
real shared package is preferred, that is a scope expansion to raise ONCE for all four
helpers (atomic-write, win-exec, wsl, text-lines), not per-phase. Filed in 100 section 5.

### 5. Deliberately NOT in this slice

- Any `wsl.exe` invocation, including `wslpath` for path translation. If a later phase
  genuinely needs it, it needs a `decodeWindowsTextBytes`-shaped decoder first (001
  section 4.1), which is a wp08 concern.
- Auto-relocating state off drvfs. Moving a user's state directory without being asked
  is a bigger decision than a diagnostic.
- Windows-side detection of "a WSL distro exists". That needs registry or `wsl.exe -l`
  parsing, which is exactly the UTF-16LE hazard this phase avoids.

## TESTS

NEW `plugins/codexclaw/components/cxc-ops/test/wsl.test.ts` - every case runs on any OS,
because every probe is injected.

1. "non-linux is never WSL" - `isWslRuntime({ platform: "win32", env: { WSL_DISTRO_NAME: "Ubuntu" } })`
   is false. A Windows process is not in WSL even with the var set.
2. "WSL_DISTRO_NAME alone is enough" and "WSL_INTEROP alone is enough".
3. "/proc/version microsoft matches" - `{ platform: "linux", env: {}, procVersion: "Linux version 5.15.90.1-microsoft-standard-WSL2" }` is true.
4. "a plain Linux kernel is not WSL" - `procVersion: "Linux version 6.8.0-generic"`,
   `env: {}` -> false.
5. "an unreadable /proc/version is not WSL" - `procVersion: null` -> false.
6. "automountRoot defaults to /mnt" when `wslConf` is null or has no `[automount]`.
7. "automountRoot parses root = /" - the short-path config, yielding `"/"`.
8. "automountRoot strips comments and quotes" -
   `[automount]\nroot = "/mnt/win" # trailing` -> `/mnt/win`.
9. "automountRoot is case-insensitive on the key" - `Root = /w` parses.
10. "a relative root falls back to /mnt" - `root = mnt` must not produce a relative path.
11. "a key outside [automount] is ignored" - a `root =` under `[network]` does not win.
12. "isWindowsInteropDir honors a custom root" - `("/w/c/Users/x", "/w")` true,
    `("/mnt/c/Users/x", "/w")` false.
13. "isWindowsInteropDir requires a single-letter drive component" -
    `/mnt/data/project` is false.
14. "a regex-metacharacter root does not throw" - root `/m+nt` matches literally.
15. "windowsHomeToWslPath lowercases the drive" -
    `C:\Users\super` -> `/mnt/c/Users/super`.
16. "windowsHomeToWslPath honors root = /" -> `/c/Users/super`.
17. "a non-Users path returns null" - `C:\Temp` -> null.
18. "filesystemTier picks the LONGEST covering mount" - a `procMounts` fixture with
    both `/ ext4` and `/mnt/c drvfs` classifies `/mnt/c/proj/.codexclaw` as `drvfs` and
    `/home/u/proj/.codexclaw` as `native`.
19. "9p is its own tier" - a `9p` mount line.
20. "UNC paths on win32 classify as unc" - `\\\\server\\share\\proj` and the
    `\\\\?\\UNC\\` form; a plain `C:\\proj` is `native`.
21. "an unreadable /proc/mounts is unknown, not native" - the distinction matters
    because `unknown` must not be reported as a clean bill of health.
