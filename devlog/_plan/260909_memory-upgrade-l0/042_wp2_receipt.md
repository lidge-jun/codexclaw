# 042 — wp2 인도 영수증

wp2 = R1 토큰 경계 매칭과 R2 한국어 어미 정규화. [PR #105](https://github.com/lidge-jun/codexclaw/pull/105), 최종 head CI pass 10 / fail 0.

## 문제의 크기

memories 285파일을 문단 청킹해 substring 히트와 단어경계 히트를 비교한 결과다.

| 질의 | 오매칭률 |
|---|---|
| `id` | 93.9% |
| `go` | 83.2% |
| `pr` | 74.5% |
| `fts` | 100% (전부 `drafts`, `conflicts` 같은 단어 내부) |

사이드카 trigram 도 같은 성질로, `git` 히트 300건 중 48건이 `digit`/`legitimate` 였다.

## 한국어는 방향이 반대였다

memory-search 가 substring 이라 `배포` 로 `배포까지` 는 이미 잡힌다. 막히는 건 사용자가 `배포까지` 라고 치는 쪽이다. 그래서 어미 절단을 `expandQueryWords` 안에서 어간을 OR-그룹 멤버로 **추가**하는 형태로 넣었고, 매칭·스코어링·발췌 코드는 한 줄도 바뀌지 않았다.

과도 절단은 어간 2음절 이상, 한글 음절만, 원문 보존 세 규칙으로 막는다. `이해`·`오해` 는 한 음절 어간이 남아 거부된다.

## 실측

`LSP` 는 3건(`NaiControlsPanel` 선두) → 2건이 되고 둘 다 독립 `LSP` 를 포함하며 fallback 경고가 없다. `3956` 은 스레드 id `01a03956-…` 를 더 이상 반환하지 않는다. `결정했지` 는 0건 → 20건이다.

## 계획과 달라진 것

경계 전용 게이팅은 코퍼스가 `PR3956` 으로 적은 경우 `3956` 에 아무 답도 못 준다. 조용한 0건이 라벨된 약한 결과보다 나쁘므로, 엄격 패스가 비면 무경계로 재시도하고 커버리지 1단위를 감점한 뒤 `lower confidence` 경고를 붙인다.

어미 절단은 계획의 고정 목록을 넘어 하-동사화 어미까지 확장했다. 계획 자신의 검증 질의 `왜 그렇게 결정했지` 가 그것을 요구한다 — `했지` 는 조사가 아니다.

stage1 SQL 은 `LIKE '%w%'` 프리필터로 두고 행 본문에 경계 재검사를 걸었다. SQL 에는 커스텀 콜레이션 없이 단어 경계가 없다.

`rollout.ts:192` 와 `chat-search.ts:94` 는 의도적으로 두었다. chat 검색의 인덱스 경로가 trigram MATCH 로 단어를 풀기 때문에 스캔 의미만 바꾸면 `test/index.test.ts:46` 의 동치 오라클이 깨진다.
