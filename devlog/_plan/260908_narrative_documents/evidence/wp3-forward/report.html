Adopt gpt-researcher for a citation-heavy research bot

Research report · 2026-09-08 · For an engineering lead choosing a framework within one week. Repository state as returned by the GitHub REST API on 2026-09-08.

A small team needs one open-source deep-research framework to carry a citation-heavy research bot. The obvious starting point no longer works: LangChain’s open_deep_research is archived, and Stanford’s STORM — the strongest citation design in the field — has not been pushed in about eleven months. That leaves a choice between lightweight recursive loops and heavyweight orchestrator-worker harnesses.

Adopt gpt-researcher. It is the only candidate that is at once actively maintained (last push 2026-08-272), permissively licensed (Apache-2.0), sized for a small team, and built around cited reports as its stated output8. Its loop is a planner/execution split with an optional recursive depth-and-breadth mode, so you start simple and turn on recursion only where a topic needs it.

Three frameworks treat citations as a design goal, and only one of them is alive

STORM is the strongest on paper: its entire two-stage design exists to produce long articles with citations, collecting references before writing rather than retrofitting them10. gpt-researcher states that its reports are “detailed, factual, and unbiased… with citations”8. MS-Agent ships a decoupled evidence store and report generator, the right shape for provenance12. dzhng compiles sources and references at report time9. DeerFlow documents sub-agent receipts, but its scope is a general super-agent harness rather than a citation pipeline11.

Because STORM is not being pushed, the practical path is to build on gpt-researcher and borrow STORM’s ordering: pin the reference set first, then write against that fixed set.

Why not the others

deer-flow is the most active and by far the most starred, but it is a super-agent harness for long-horizon work with sandboxes, memory, skills, and a message gateway. Its 897 open issues5 and the sheer breadth of its README are the signal: adopting it means inheriting a platform. Choose it only if the roadmap also wants coding and long-horizon surfaces.

ms-agent is current and has the cleanest evidence-store story. It claims #2 open-source (#5 overall) on DeepResearch Bench at 55.3112, but that is the project’s own README; the leaderboard was not opened, so the standing is unverified here.

dzhng/deep-research is the best code to read and the worst to depend on: deliberately the simplest implementation of the loop, in TypeScript, five months without a push. Copy the loop, skip the dependency.

open_deep_research is archived1. deepagents in the same organization is live7, but no opened source declares it the successor, so that stays an open question.

What this does not cover

  • Architecture claims come from READMEs, not from reading loop implementations; a README can describe intent the code drifted from.
  • No output-quality comparison was run. Nothing here says which framework produces better citations, only which are designed around them.
  • Star counts measure attention, not adoption of an architecture.
  • STORM’s eleven-month gap is a fact; calling it abandonment is an inference. No maintainer statement was opened.
  • The candidate-completeness sweep was not run within budget, so a leader outside these seven repositories could have been missed.
  • MS-Agent’s benchmark standing is self-reported.

Open questions

  1. Is deepagents the official successor to open_deep_research?
  2. Does MS-Agent’s DeepResearch Bench claim hold on the independent leaderboard?
  3. Is STORM deliberately finished, or unmaintained?

Next steps

Prototype on gpt-researcher this week. Run the standard planner/execution pipeline first, enable the recursive depth/breadth mode only for topics that need it, and adopt STORM’s reference-before-writing ordering for citation fidelity. Revisit deer-flow only if the roadmap grows past research into long-horizon agent work.
