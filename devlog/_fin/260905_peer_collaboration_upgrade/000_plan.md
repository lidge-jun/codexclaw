## Loop specification

- Archetype: spec-satisfaction delivery of the chosen skill-first direction. Model
  scenarios check decisions, not a claim of optimized production performance.
- Trigger: explicit HOTL update request with parallel subagents.
- Outcome: discoverable autonomous peer guidance for coding, research and loops,
  preserving independent user goals, question-only wake and explicit-stop boundaries.
- Non-goals: new team/task/broker/DB, runtime enforcement, unconditional polling,
  other worktrees, hooks/config, install/release/push, live peer sends as test fixtures.
- Verification: exact-path docs/link/patch/frontmatter checks; focused existing
  catalog/inventory/manifest suites; blind model scenarios plus independent audit.
- Stop: both registered work-phases pass C and D with genuine receipts.
- Memory: this unit, bound goalplan and ledgers. No memory-store changes.
- Resources: existing local tools and model calls, no new credentials or purchases.
  User set no token/cost or subagent-count cap; host concurrency and disjoint scopes
  apply. Review progress within 120 minutes; no long-lived external jobs.
- Escalation: main reclaims failed bounded lanes; scope expansion is a P amendment,
  not an improvised dispatch. Wait timeout is not failure. External authority gaps
  are reported as NEEDS_HUMAN/UNSAFE, never evaded.
